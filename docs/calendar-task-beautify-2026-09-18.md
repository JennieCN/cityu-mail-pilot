# 日历待办纯规则美化（2026-09-18）

背景：`/api/tasks/export.ics` 导出的日历条目是纯文本拼接
（`【急】行动原文（截止 9/18/2026 23:59）`），并且所有任务都是**全天事件**——
即使截止时间带 `23:59` 这样的精确时刻，日历里也只显示成"全天"色块。
本次在不引入任何模型调用（"规则层纯美化"）的前提下解决这两点。

## 改了什么

`pilot_app/taskexport.py`（全部新逻辑都在这一个模块）：

1. **任务类型推断** `task_kind()`：10 组中英关键词（作业/考试/注册/缴费/图书/求职/
   活动/申请/确认/其他）对**行动文本**做一次匹配，产出类型标签。
   只看 action、不看 subject——subject 与行动经常无关
   （"图书馆逾期通知"里可能是"阅读第 2 章"），错误标签比"✅"更糟。
   这个函数是留给 Jev 决策层的接缝：将来换成一次真实的 `choice` 调用即可，
   下游（emoji、CATEGORIES）不需要再改。
2. **美化标题** `pretty_title()`：`📝 【急】提交作业到 Canvas ⏰ 9/18 23:59`。
   - 类型 emoji 前缀；
   - 截止日期缩短为 `M/D HH:MM`（年份在 ±1 年内省略——日历自己会显示年份，
     标题里三个数字读起来像两个矛盾的日期）；
   - **日期只出现一次**：能缩短时用 ⏰ 标签**替换** `line_for` 的"（截止 …）"
     后缀（全文仍在 DESCRIPTION 里）；行动已自带截止时间时不加任何后缀
     （沿用 `_already_states` 的按数字比较规则）。
   - `line_for()` 本身**语义不变**（清单粘贴、DESCRIPTION 第一行仍用它），
     美化只发生在日历 SUMMARY 层。
3. **定时事件**：截止时间带明确 `HH:MM`（含全角冒号）的任务，从全天事件升级为
   用户时区下"截止时刻起 1 小时"的定时事件（`DTSTART;TZID=…`），手机日历可以
   真正提醒。配套：
   - 文件内嵌最小 `VTIMEZONE`（RFC 5545 要求 TZID 引用必须在同文件有定义；
     本项目时区选项都是无 DST 的亚洲时区，固定偏移是诚实的）。
   - 时区字符串先过 `_safe_zone()`：非法/敌意值（CRLF 注入、不存在的 zone）一律
     降级回全天事件，绝不抛错、绝不注入结构。`web.py` 从用户 profile 取
     timezone（与"今天是哪天"同一来源）传入 `build_ics`。
   - 没有时刻、没有时区、时区非法 → 仍是原来的全天事件（`VALUE=DATE`，
     DTEND 排他日）。
4. **CATEGORIES** 带上类型标签：`CityU Mail Pilot 待办,作业`，客户端按日历
   分类显示/筛选时可用。

`pilot_app/web.py`：`export_tasks_ics` 传入用户时区（`task_day_view` 的
`export_title` **保持 `line_for`**，见下面「评审改掉的四处」）。

## 刻意不做的

- **不动 `line_for` 的输出语义**：它是"唯一决定措辞的地方"，纯文本清单
  （iOS 提醒事项 / Google Tasks 粘贴）依赖它；美化只叠在展示层。
- **不做时间点归一化**（23:59 之类不做"提前 30 分钟提醒"之类的加工）：
  截止时刻是邮件说的，不是我们猜的——和 `sanitize_calendar_dates` 同一条铁律。
- **emoji 不进清单**：粘进提醒事项的清单不需要它，且旧版测试断言
  （`【急】`开头）继续成立。

## 测试

`test_taskexport.py` 44 条全过（新增 15 条：类型推断 6、美化标题 4、定时事件
5——含敌意时区注入与坏时区降级）；`test_tasks` / `test_web` / `test_reports` /
`test_prompts` 共 142 条全过。

注：本机跑测试需 `pip3 install cryptography`（`security.py` 的 SecretBox 依赖），
与本次改动无关，原仓库 CI 环境已有该依赖（requirements.lock）。

## 附录：并入上游时的评审（2026-09-19）

这份改动是直接推到公开仓库 `main` 的（提交 `ca1b71ad`）。合并进上游前逐行审过，
改掉四处、保留其余。改的地方都有测试盯着，理由写在这里：

1. **`CATEGORIES` 的分隔符被转义了。** 原来是
   `_escape(CALENDAR_NAME + ',' + 标签)`，于是输出
   `CATEGORIES:CityU Mail Pilot 待办\,缴费`——客户端看到的是**一个**名字里带逗号的
   分类，「按类型筛选」这个卖点当场落空。RFC 5545 里 `CATEGORIES` 是**列表**属性：
   分隔符是真逗号，只有**值里面**的逗号才转义。现在改成逐个转义再用真逗号连接。
   原来的断言用 `assertIn`，两种写法都会过——所以新断言数**值的个数**。
2. **`__all__` 里有一个不存在的名字** `kind_of`：`from pilot_app.taskexport import *`
   会直接 `AttributeError`。1878 条测试没有一条发现它，因为没人从 `__all__`
   那一侧读这个模块。删掉它，并补一条通用守卫（`__all__` 里每个名字都必须真的存在）。
3. **`export_title` 曾经指到美化标题上，而它是「复制成清单」那一行。**
   `app.js` 用它拼 `- [ ] …` 粘进 iOS 提醒事项 / Google Tasks，于是 emoji 和 ⏰
   会跟着粘过去——而本文件上面「刻意不做的」第三条写的正是 emoji 不该进清单。
   两份**设计**都对，错的是一个字段被两个消费者用了。现在 `export_title` 回到
   `line_for`，日历里的漂亮标题只在 `build_ics` 内部生成；浏览器套件里也加了一条
   「复制出来的清单不含图形字符」。
4. **「本项目时区选项都是无 DST 的亚洲时区」这个前提不成立。**
   `index.html` 的「时区」是**自由文本输入框**，不是选项列表——用户填
   `America/New_York` 就会拿到一个固定偏移的 `VTIMEZONE`，夏令时那半年**差一小时**
   且没有任何报错。修法不是补全 DST 转换表（那是一整块新逻辑），而是**说实话**：
   `_safe_zone()` 现在也会拒掉偏移一年里会变的时区，降级回全天事件。
   另两处小修：`_deadline_clock()` 改取**最后一个**时刻（与
   `reports.deadline_of` 一致——一行里出现两个时刻时，App 说 23:59 而日历在中午响
   是迟早会发生的事，虽然现在线上 304 条任务里 0 条命中）；`_short_deadline()`
   的「今年是哪年」改成由调用方传入的 `today`，与模块里其余部分同一个来源。

保留的部分：类型推断只看 action（这条判断是对的，且量过）、「截止时刻起 1 小时」的
定时事件、标题里日期只出现一次、敌意时区不注入结构。**另外把「其他」类型的 emoji
从 `✅` 去掉了**：生产实测最近 7 天 304 条任务里 **52% 落到 `other`**，而 ✅ 挂在一条
**还没做完**的待办前面，读起来是「已完成」——认得出类型才戴帽子。

评审时也量了这份改动的实际影响：304 条任务里 140 条有截止时间，其中 **35 条（12%）**
会从全天事件变成定时事件；类型分布 `other 52% / 申请 21% / 活动 8% / 确认 8% /
求职 6% / …`。批量案例表 `tools/taskexport_batch_check.py` 100 条在改后仍全过
（其中「伦敦时区 +0100」那条按新行为改成了「降级全天」）。
