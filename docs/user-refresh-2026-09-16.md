# 替用户「点一次」那三个测试（v0.63.43，2026-09-16）

> 用户原话：**「帮我做对每一个用户都可以一键刷新他们所有状态的按钮，我要这个按钮可以选择全部人也可以单某个人」**。
> 姊妹篇（第三种「卡住」）见 `docs/never-forwarded-2026-09-16.md`。

## 1. 为什么需要它

四盏灯里三盏的规则是「**有人真的测过一次、而且成功了**」（`Database.verification_lights`）：

| 灯 | 证据 |
|---|---|
| 收信 | 邮箱轮询或只读验证成功过（`last_verified_at` / `last_polled_at` + 错误列为空） |
| 模型 | 按**这个账号**测过一次（`connections.last_test_at` + 错误列为空） |
| 搜索 | 同上（另一条 `kind`） |
| 出报告 | 真的生成**并且**交给 SMTP 成功 |

而这三盏灯的点亮动作，只有账号主人自己能做（设置页的三个测试按钮）。**唯一不会去点它的人，
正是账号的主人**：对他来说什么都没坏，或者他根本没打开过那一页。运营者能看见红灯，
却一直没有把它点亮的办法。

## 2. 接口

```
POST /api/admin/users/{user_id}/refresh
body: {} 或 {"targets": ["mailbox","model","search"]}
```

* `targets` 省略 = 三件都测；给了但不是字符串数组 → **422**；一个可测的都没有 → **422**；
  未知用户 → **404**；非管理员 → **404**（与其它 `/api/admin/*` 一致）。
* 每项结果：`{key, label, ok, error, own, note, seconds}`，另有刷新后的 `lights`。
* **一次只处理一个账号**：前端循环。理由写在该路由的 docstring 里——一个卡住的邮件服务器
  不该把一整个大响应拖过 nginx 的超时，运营者也该能中途停下，而停下来时前面的结果都还在。
* 审计：`action=user_refreshed`，detail 只记 `targets=… ok=N failed=N`（计数，不含读数，也不含地址）。

### 它刻意不做的三件事

1. **不碰「出报告」**。那盏灯只能由一封真的来信换来（读信 → 模型 → 邮件发出去）。
   做成按钮就等于把全项目唯一的端到端证据变成一个装饰——一个会撒谎的面板比没有面板更糟。
2. **不动邮件**。邮箱那一路走的是与设置页同一个只读 `BODY.PEEK` 路径（`service.test_mailbox`），
   不落库、不标旗标、不删信、**不移动游标**（`record_mailbox_verification` 从不写 `last_uid`）。
3. **不把共用的 key 说成是他自己的**。没有 `connections` 行的账号走平台兜底 key：
   测试真的跑了，但**没有行可以记**（`record_connection_result` 只 UPDATE 已有行），
   所以响应里带 `own=false` 与一句说明，而不是让「刚测成功」和「从没测过」同屏出现。

## 3. 界面

「已注册用户」面板顶部一条工具条：**全选** / **刷新勾选的（N）** / **刷新全部（N）** / **停止**，
以及一行说明（几个账号没有自己的 key、会由平台出钱）。每一行自己的「刷新状态」按钮走**同一段循环**，
所以「全部人」和「某一个人」不会变成两套行为。

* 逐个账号地跑，进度行写「正在刷新 3/7：someone@example.com……」；结果区逐项列出
  `✓ 收信（1.4 秒）` / `✗ 模型（0.3 秒）：尚未配置模型 API`。
* 失败**不会**让整批停下来（一个账号 429 或者一个坏邮箱不该连累其余的人）。
* 跑完**重新拉一次** `/api/admin/users`：灯是服务端算的，不重新拉就看不到刚刚发生的事——
  而「刷新成功但灯没变」正是这个按钮要消灭的那类误会。重新拉失败会明确说出来。
* 「刷新全部」会先 `confirm`，写清会真的调用多少次、多少个用平台兜底 key、以及不会改动任何邮件。

## 4. 验证

* 单测（`test_admin.py`）：真跑三个探针并检查灯**真的变了**；失败要**记下来**（灯变红、错误进 detail）；
  兜底 key 的 `note`；`targets` 的四种坏输入 422、未知用户 404、普通用户 404；审计计数。
* 浏览器（`admin_edit_check`，夹具的邮箱本来就连不上）：点某一行的按钮，**看它打的是不是那个账号的
  接口**；结果里三项逐条列出且如实报 ✗；**「出报告」不许因此变绿**；全选 → 按钮上带人数 → 全不选 → 回到 0。
* 真机（生产，2026-09-16）——对那个正在调查的真实账号走真接口（一次性运营者会话，用完即删）：

```
POST /api/admin/users/<id>/refresh -> 200
  {"key":"mailbox","ok":true,"own":true, "seconds":0.3}   ← 真的连了一次 IMAP（只读）
  {"key":"model",  "ok":true,"own":false,"seconds":0.7}   ← 平台兜底 key，真的调了一次
  {"key":"search", "ok":true,"own":false,"seconds":0.6}
灯：收信 ✓（刚被点亮）· 模型/搜索 仍未测 · 出报告 不变
```

三件事各自证明了：**探针真的跑**（0.3–0.7 秒，不是缓存）、**兜底 key 不写进账号自己的记录**
（`own=false` 且灯保持「从没测过」，响应里那句说明就是给这个看的）、
**「出报告」没有被动过**。整个请求 3 秒以内，nginx 那 330 秒的窗口用掉零头。
