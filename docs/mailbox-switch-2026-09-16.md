# 一条死路要给出路：「换一个能用的邮箱」（v0.63.49，2026-09-16）

> 起因是运营者发来的一张截图：一个真实账号（微软个人版）的「邮箱设置」页上，红框写着
>
> > 检查失败：这个邮箱的服务商已经停用「账号密码 / 授权码」登录（微软 Outlook、Hotmail
> > 已强制改用 OAuth）。请换一个支持授权码的邮箱作为转发邮箱，例如 QQ 邮箱、Gmail 或 163 邮箱。
> > 这不会丢邮件；请按提示修正后重试。
>
> 每个字都是真话，**而它是一条死路**：页面上没有任何按钮，用户唯一能做的事就是**把同一个
> 邮箱再填一遍**。他配的私人邮箱就是那个 @outlook.com，他也拿不出第二个邮箱来。所以他
> 反复重试、反复失败——而失败的样子和「你太笨」长得一样。
>
> 用户的原话是两个字：**「解决」**。

## 一、这件事的形状：不是错误提示写错了，是「下一步」缺失

| | |
|---|---|
| 事实 | 微软个人版（Outlook / Hotmail / Live / MSN）已经停止用账号密码 / 授权码取信 |
| 我们做对的部分 | 判出来了（`Database.mailbox_needs_another_provider`）、说清了（不是你的错）、还专门写了一封信（`provider` 那一组） |
| 我们做错的部分 | **界面只说了「换一个邮箱」，没有让他换**。文字是给能自己想办法的人看的；这里的人需要的是一次点击 |
| 更隐蔽的一半 | 就算他自己想通了去注册一个 QQ 邮箱，**CityU 那条转发规则还指着旧地址**——邮件继续转到那个用不了的邮箱里。表现是「换了邮箱还是收不到」，看起来像换邮箱没用 |

## 二、改法：事前预警 + 一键换 + 三步说清

### 2.1 事前：还没连就知道这家不行

在「私人转发邮箱」下面加一格 `#mail-switch`。它出现的第一个时机是**用户刚打完一个
@outlook.com 地址**——此时我们还没连过任何东西，但这件事是确定的：

> **这个邮箱一定连不上，先换一个**
> 微软的 Outlook / Hotmail / Live 个人邮箱已经不能用授权码收信，选它一定会连接失败。
> 1. 换一个还能用授权码的邮箱（下面任选一家），把新地址填到上面那一格。
> 2. 打开 CityU 的转发设置，把转发地址改成这个新邮箱——不改的话，邮件还是转到旧邮箱里。
> 3. 去新邮箱拿到授权码填到第 3 步，回来点「加密保存」，再点「只读连接测试」。
> 〔换成 QQ 邮箱〕〔换成 163 邮箱〕〔换成 Gmail〕

**「一定」这个词是有依据的**：`blocked_reason` 只标在一个预设上（Outlook），而它的判据
与后台那套是同一份数据（见 §三）。

### 2.2 事后：服务端确认过，措辞就换成已发生

同一格在**真的连过并被拒绝**之后出现（`/api/me` 的 `needs_another_provider`），标题变成
「**这个邮箱的服务商已经不给用授权码了——重填授权码不会成功**」。预测与已发生，是两句话，
因为对用户的含义不同：前者是「别选它」，后者是「你没错，重试没有意义」。

锁存这一点：一旦服务端确认过，本次会话里就按「已发生」说——换邮箱之后 `state.mailbox`
还是旧那一行（要等用户保存），措辞在两种之间来回跳会让人以为问题变了。

### 2.3 一键换：切服务商、清掉用不了的地址、把后果说全

点「换成 QQ 邮箱」之后发生四件事：

1. 服务商下拉切到 QQ，**服务器地址与第 3 步的教程一起换**（不然用户拿到的是 Gmail 的教程）；
2. 那个用不了的地址**被清空并聚焦**（留着它只会被再次提交）；
3. 「报告发到哪里」如果原样指着那个旧邮箱，**也一起清空**（回到「留空 = 发回私人邮箱」）——
   否则报告会继续寄到一个我们再也读不到的地址；
4. 顶部的状态条（就是刚才那条红字的位置）说清后果：
   「已切到 QQ 邮箱。上面那一格已清空（**那个用不了的地址**不再使用）——先注册一个
   QQ 邮箱、拿到授权码填回去，**再去 CityU 把转发地址也改成新邮箱**，然后回来保存并测试。」

**反馈写在状态条上，不留在那一格里**：那一格马上要收起来，把话写在正在消失的东西上等于没说。

### 2.4 那一格自己收起来

切到能用的服务商之后，黄框**必须消失**——一个写着「这个邮箱一定连不上」的框停在 QQ 地址
旁边，会和用户刚做的事自相矛盾。规则因此是：**这一格只说「他现在选的那家」**，不说历史。

## 三、判据只有一处，页面与信件不会各说各话

| 事实 | 住在哪 | 谁在读 |
|---|---|---|
| 这家服务商在哪些主机名上已经死了 | `mailpresets.MAILBOX_PRESETS`（outlook 的 `blocked_reason` + `blocked_hosts` + 域名） | 界面（按钮与预警）、后台、提醒信 |
| 一个邮箱是不是「服务商的问题」 | `Database.mailbox_needs_another_provider`（两条证据：主机名 / 错误文本） | 后台红绿灯、提醒分组、`/api/me` |
| 清单本身 | `mailpresets.BLOCKED_PROVIDER_HOSTS` —— **由预设算出来的**，`Database._PROVIDER_BLOCK_HOSTS` 直接引用同一个对象 | 上两行的共同底座 |

**是引用，不是抄写**：`self.assertIs(...)` 钉住（相等不够——两份字面量今天相等，明天有人改一份就漂）。
顺着这条不变量还补上一个真实缺口：`msn.com` 也是微软个人版，却不在旧清单里。

推荐哪几家也是数据（`recommended: True` → `recommended_alternatives()`），而**提醒信里那三家
是手写的**，所以有一条联合断言：界面推荐的每一家，短名字都必须出现在
`setup_reminders._switch_mailbox_steps()` 里（`QQ 邮箱 / 163 邮箱 / Gmail` 对 `QQ 邮箱、163、Gmail`）。
两份清单迟早会漂，漂的那天必须有人红。

**客户端不重新判一遍**：`app.js` 里不许出现 `outlook.office365.com`、`hotmail.com`、`OAuth`
或「已强制改用」（有一条静态断言盯着）。它只读服务端给的布尔量。

## 四、套件抓到的一个真 bug：真的点它，什么也没发生

`setup_guide_check` 加完断言之后：**`element.click()` 好的，用真实坐标点坏的**。

根因：输入框的 `change`（失焦）会重画那一格，而**点按钮本身就会让输入框失焦**——
mousedown 之后、mouseup 之前按钮被替换掉，浏览器于是把 `click` 派发到两者的**最近公共祖先**
（那一格 `div`）上，委托处理器 `event.target.closest('button[data-provider]')` 拿到的是 `div`，
返回 null，什么也不做。

修法：**内容没变就不碰 DOM**（把「是否已观察」+ 被挡的预设 + 备选 id 串成一个签名，
签名相同直接 return）。这也是这个项目一再学到的那条：**重渲染会吃掉用户正在做的那一下**。

教训一句话：**`element.click()` 绕过命中测试，所以「点了有用」这件事只有真实坐标能证**——
2026-09-16 同一天里，这条已经是第二次（v0.63.41 的公告按钮是第一次）。

## 六、没做的那条路：真的支持微软 OAuth

要让 @outlook.com 这类邮箱**继续可用**，唯一的路是给微软做 OAuth（SASL XOAUTH2）：

* **成本**：要在 Azure 注册一个应用（client id/secret，**这是新的凭据，只有运营者能提供**）、
  实现授权码/设备码流程、存 refresh token（用户改密码要重新授权）、每个用户都要过一遍微软的
  同意页；邮件正文的读取仍然走 IMAP，只是换了认证方式。
* **它会改变产品的形状**：「填一个授权码」变成「跳到微软登录」——而本项目的铁律是**不拿用户的
  学校密码**，私人邮箱那一步现在是自足的、不需要第三方审批的。
* **对企业的 M365 账号也不一定有用**：很多学校/公司管理员**直接把 IMAP 关掉了**，
  OAuth 也进不去。

所以这一版走的是「引导换一个还能用的邮箱」，代价是用户要新注册一个邮箱；
要不要再走 OAuth，是运营者的决定（要新凭据、要过审、要改产品形状），不是这一轮能自己拍的。
