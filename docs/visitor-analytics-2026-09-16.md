# 有多少人看过我的网页（v0.63.31）

> 用户原话：**「帮我做一个可以检测有多少人浏览了我的网页的检测，最好带上他们的地址」**。
> 三个决定由用户拍板：**地理 + IP 原文都要看**、**但 IP 不落盘（只存键控摘要）**、**已有的 nginx 日志要导进来**。

## 1. 先查了开源先例，再决定做进应用

按项目惯例先做了先例检索（当天核对过 license 与活跃度）：

| 项目 | 许可 / 栈 | 结论 |
|---|---|---|
| [GoAccess](https://github.com/allinurl/goaccess) | MIT · C · 单二进制，解析 nginx 日志 | **参考未采用**：零新增采集、能出历史报表，但没有「打开后台就能看到数字」的形态，且它自己也要一份 GeoIP 库 |
| [GoatCounter](https://github.com/arp242/goatcounter) | Go · 单二进制 + SQLite | **不采用**：功能最贴合，但它是**另一套服务**——自己的库、自己的登录、自己的公网入口，等于在 2 核 2G 上再养一套系统并多开一个对外面 |
| [Umami](https://github.com/umami-software/umami) MIT · [Plausible](https://github.com/plausible/analytics) AGPL · [Matomo](https://github.com/matomo-org/matomo) GPL | Node+Postgres / Elixir+ClickHouse / PHP+MySQL | **不采用**：每套都要再拖一个数据库引擎进来，与「一个 Python 应用 + SQLite」的现状不成比例 |

于是做进现有应用：服务端计数、复用 SQLite 与后台登录态，**零第三方 JS、零 cookie**。这不是省钱，是**架构比例**：一个 7 人内测站不需要为「有多少人看过」再引入一套栈。

## 2. 用户的两个要求看起来矛盾，其实可以同时成立

- 「要看到 IP 原文」
- 「不存 IP 原文（只存摘要）」

办法是把**看到**和**存下**分成两件事：

| | 存在哪 | 活多久 | 谁能看到 |
|---|---|---|---|
| 键控摘要（`SecretBox.anonymized`） | 数据库 `page_views.client_hash` | 保留期内（默认 180 天） | 后台只用来数「约多少人」 |
| **完整 IP** | **只在 web 进程的内存里**（环形缓冲，最多 200 条） | 重启即消失 | 后台「最近访问」那一栏 |

于是「最近访问」里能看见真实地址，而数据库里**没有任何一列是地址**——`test_analytics.py` 的
`test_a_visit_is_counted_without_the_address` 把整行拍平成字符串来断言这一点。
**附带的好处是备份**：库每天被备份（可能推到异地），地址从来没进过库，也就从来没进过备份。

摘要用的是 `security.SecretBox.anonymized`——和留言板同一个函数。**不为同一件事写第二个定义**，
理由那句注释也已经写过：IPv4 空间只有 2^32，裸哈希几分钟就能枚举回来，所以必须是键控摘要。

## 3. 顺手修掉一个真 bug：程序看到的「访客 IP」永远是 127.0.0.1

`web.py` 一直用 `self.client_address[0]` 当访客地址，而它**跑在 nginx 后面**：那是 nginx 的地址，
所以每个访客都是 `127.0.0.1`。nginx 一直在发 `X-Real-IP`，代码里**从来没有人读过它**。

后果不止统计：**留言板的「每客户端 5 次/小时」其实是全互联网共用一个额度**——
第一个刷 5 次的人会把所有人挡在外面。上线至今 0 条留言，所以没有真实受害者，但这是个真的坏闸门。

修法只有一处：`analytics.client_ip(peer, headers)`——**只有连接本身来自本机回环时才相信 `X-Real-IP`**
（那正是我们自己的 nginx），否则用 socket 对端地址。**不读 `X-Forwarded-For`**：它是个列表，
左边的项由客户端控制，一个可信头比解析一个不可信列表安全。

### 连带必须一起改的：所有**会落盘**的 client

修好 IP 来源之后，原来存 `127.0.0.1` 的地方就会开始存**真实访客地址**。审计日志与内测申请表
都存着这个值（25 处），所以规则定成一句话：**落盘的一律是摘要，原文只留内存**。
`_client_label(request)` 是唯一入口。审计里「谁做的这次操作」仍然可比对（同一人同一摘要），
而真正的原始地址**在 nginx 自己的访问日志里**——那份日志不进数据库、不进异地备份。

## 4. 机器人单独算，因为它占大多数

这台机器在公网地址上，开站几小时内就有扫描器上门（`odin-scanner/0.4`、`netsystemsresearch`、
`paloalto` …）。一个把扫描器和真读者加在一起的「访客数」是没法用的数字，所以：

- `bot` **入库时打标**（不是丢弃），后台两个数并排显示；
- 顶层数字（今天 N 次 / 约 M 人）**只算人**；
- 面板里那 8 行「机器人最爱敲的路径」是白送的副产品，对判断有没有人在扫很有用。

`DNT: 1` 与 `Sec-GPC: 1` **完全不记**——少一点准确度，换一句不带星号的承诺。

## 5. 地理：离线库，不把访客地址发给第三方

用 [DB-IP Lite](https://db-ip.com/db/lite.php)：免费、**不用注册**、CC BY 4.0、每月 1 号更新。
`manage geoip-update` 下载 → 建成一个**独立的 SQLite**（约 51 MB，71.7 万条区段，本机构建 7.6 秒），
放在 `INFE_PILOT_GEOIP_DB`（默认 `/var/lib/cityu-mail-pilot/geoip.sqlite3`）：

- **不进主库**：主库每天被备份，把 51 MB 的公开参考数据塞进去，等于让每份备份都胖一圈；
- **不进仓库/发布包/源码快照/开源导出**：它是构建产物，理由与安卓 APK 相同；
- **查询零网络**：访客地址不会被发出去问（留言板那五条反滥用里就写着「不把访客 IP 交给第三方」）。

两种数据集：`country`（4.5 MB，默认）与 `city`（85 MB，19 倍）。国家码→中文名是模块里的一张表，
因为**DB-IP 的 CSV 只给代码不给国名**；表里没有的代码**原样显示**（`QQ`）而不是猜一个国名。

## 6. 历史：把 nginx 自己的日志导进来

站从 9/15 就在跑，日志还在（`/var/log/nginx/access.log*`，含 `.gz`）。
`manage analytics-import-nginx` **默认只预演**（和 `notify_stalled`、`cleanup_local` 一致），`--apply` 才写：

- 解析 combined 格式，**月份用自己那张表**（`strptime("%b")` 依赖 locale）；
- 时间戳从 `+0800` 本地时间**转成 UTC**（差 8 小时是这类导入最经典的错）；
- **文件顺序按 logrotate 语义**（`.10.gz` 比 `.1` 老）——否则「导入最早的 N 条」会变成导入最新的 N 条；
- 地址在导入时摘要化，国家在导入时解析（那时地址还在手上，这是唯一能解析的时刻）；
- 导入的行 `source='nginx'`，**不会出现在「最近访问」**（那一栏只讲"现在"）。

生产上日志是 `root:adm 640`，服务账号读不到，所以导入前先把日志**复制到 `/tmp` 再改属主**
（步骤写在 AGENTS.md §5）。

## 7. 隐私政策同步（这次是加一节，不是改一句话）

政策新增**第 8 节「访问统计」**，后面几节顺延（8→9 … 12→13）。它必须与代码一致，
`test_compliance.test_privacy_policy_covers_the_visitor_counter` 盯着六件事：
地址不写进数据库、原文只在内存、摘要无法还原、DNT/Sec-GPC、DB-IP 署名、保留期**从代码里读**
（不是写死的 180）——最后这条是上一轮备份那节的教训：**把页面上的错数字钉进测试，等于把错误冻结**。

## 9. 真机验收抓到的两个 bug（本机测试都盖不住）

**① DB-IP 对 `Python-urllib` 的 UA 返回 403。** 本机测试用的是 `--source`（本地 CSV），
所以**下载那几行代码从没在本机跑过**；到了服务器上第一次跑就 403。curl 同一个 URL 是 200——
说明网络没问题，是 UA 被挡。改成 `Mozilla/5.0 (compatible; cityu-mail-pilot; +https://github.com/…)`
（compatible 是「我不是浏览器」的常规写法，不假装自己是 Chrome）。

**② `geoip.lookup()` 每次调用泄漏一个文件描述符**——这一条更严重。Python 的
`with sqlite3.connect(...)` 是**事务**上下文管理器：它 commit/rollback，**不 close**。于是：

- 1,919 行的日志导入**只写进去 586 行**，后面的每一行都「打不开数据库」，
  而当时的逐行导入把异常吞掉了，摘要照样说「完成」；
- 更要命的是**请求路径**：每次页面访问泄漏一个 fd，1024 个之后 web 进程就再也开不了数据库——
  也就是**大约一千次浏览之后网站开始 500**。真机实测：2,000 次查询后
  `OSError: Too many open files`。

修法是 `contextlib.closing(...)`。**回归测试故意不数 fd**：在 macOS 上，泄漏的连接会被引用计数
立刻回收，400 次泄漏调用只涨 1 个描述符——**那种测试在本机永远是绿的**。改成
「把每个连接都强引用住，然后断言它已经被显式关闭」，反向验证过（改回旧写法当场红）。
**教训：症状（描述符数量）是平台相关的，机制（有没有 close）才是可移植的断言。**

顺带把导入改成**一个事务批量写入**（原来一行一个连接，既慢又在和 web 进程抢锁），
并加了**部分唯一索引**（`WHERE source='nginx'`）让重复导入成为空操作：
生产上第二次导入输出「新增 0 条，已存在 1919 条」。活人的行**不**去重——
同一个人同一秒刷新两次是两次浏览。

## 10. 已知的边界（写在面板里，不藏着）

- **「约 N 人」是估算**：按摘要去重，同一 NAT 下算一个、手机换网算两个；
- **导入的记录看不到 IP**：那部分历史只以摘要+国家入库；
- **「最近访问」重启即空**，也不含导入的行；
- **国家/城市依赖离线库**：没建库时那一栏是空的，面板会直接告诉你去跑哪条命令；
- **保留期默认 180 天**（`INFE_PILOT_ANALYTICS_DAYS`），到期在请求路径上顺手清理（每小时最多一次）。

## 11. 运营者自己不算访客（v0.63.38–0.63.39）

用户看过面板之后说了两句话：「**把我自己的记录删了**」「**为什么那么乱**」。

### 11.1 「不算访客」有三个出口，少一个都会被他看见

| 出口 | 旧行为 | 现在 |
|---|---|---|
| 计数（人/次/页面/来源/国家/按天） | 他在 `/` 上的访问**被记成匿名访客** | 行上打 `admin` 标记，**所有聚合 `admin=0`** |
| 内存里的「最近访问」（唯一带完整 IP 的地方） | 照样列出来 | `remember()` 跳过运营者条目 |
| 已经记下的行 | 没有删除入口 | 面板上「删掉我自己的记录」 |

第一行那个 bug 是**写测试时断出来的**：`_record_visit()` 原来只在请求已经要求登录时才拿得到
`request.user`，而介绍页 `/` 不要求登录——**签着到的运营者在那里就是匿名**。现在记录器自己解析
会话（`_visit_identity()`：`request.user` 优先，否则用 cookie 查 `session_user`）。

第二行值得单独说：那份列表是给他看「谁来了」的。他自己那几次他已经知道了，而且
**他的页面加载会把真访客挤出 200 条的缓冲**——一个 2 核 2G 的内测站，运营者一天看几十次后台，
被挤掉的恰好是他想看的人。数据库里仍然留着这些行（「删掉我自己的记录」要有东西可删，
测试也钉住「存下来但不计数」）。

### 11.2 删除按钮删的是两类，且记得住

- `admin=1` 的行；
- **来自他现在这个 IP 摘要**的行——历史行没有标记，但那把摘要认得出「这个地址」。

**不做这一步就会反复**：导入的去重键是 `(时间, 页面, 摘要)`，行删了去重记录也没了，
下一次 `manage analytics-import-nginx --apply` 会把他刚清掉的历史**原样搬回来**，
而面板上看起来像「删除没生效」。所以删除时把摘要写进 `page_view_ignored`，导入跳过它们
（输出里单独一行「运营者：跳过 N 条」，不混进「已存在」）。

**只在导入路径上生效**，实时路径不查这份名单：实时那一次知道是谁的会话（`admin` 标记就够了），
而按地址排除意味着 DHCP 换手之后可能把一个真访客**静默**丢掉——那是比多算一次更糟的错误。

### 11.3 生产上怎么找出「他自己的地址」

**看 nginx 日志里哪些地址从 `/api/admin/*` 拿到过 2xx**：只有管理员会话能产生这种行
（非管理员在 `_require_admin` 那里就是 404，不会留下 2xx）。数出来 19 个（校园网多段、
中国移动、两个境外地址——他授权的那位管理员也在其中，两位都是运营者，都算「自己」）。

删除**走真实接口**（`POST /api/admin/analytics/purge`）：从回环发起并带 `X-Real-IP`，
因为 `analytics.client_ip()` **只在本机回环时才相信这个头**——这不是绕过校验，是走它设计上
唯一信任的那条路。会话由脚本临时造（10 分钟有效、`finally` 里删掉），运营者的密码不经过我。

结果：**删掉 1269 行**（19 个管理员地址 1243 + 本机出口 26），库里 **1957 → 688 行**，
`admin=1` 剩 0 条，忽略名单 20 个摘要，审计留 `analytics_operator_purged`。

### 11.4 面板的形状

四个数字卡（今天·人数 / 今天·浏览 / N 天·人数 / N 天·机器人）→ 最近 7 天表 →
三张「前 5 名」→「最近访问」折叠（限 20 行）。上一版是六张表平铺，第一眼看不到「有多少人」。

**重排时保住那些被断言钉住的句子**（note 的 `今天 N 次 / 约 M 人`、`只在内存里`、DB-IP 署名、
`30 天`）：套件断的是这些字符串，句子搬家时一起搬，断言才有意义。
