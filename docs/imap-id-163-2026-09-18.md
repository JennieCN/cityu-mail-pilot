# 163 收不了信：一个必须发的 IMAP `ID`（2026-09-18，v0.63.77）

> 用户看到的是后台那句「**无法以只读方式打开 INBOX**，自 2026-09-18T01:09:09 起持续」。
> 这篇是它真正的原因、怎么量出来的、改了什么，以及**为什么以前的检查全都没看见它**。

## 1. 起因

运维助手报：**某个 163 账号**收信时打不开 INBOX，邮件不丢。
同一份报告里还有一句自相矛盾的话：「这个账号**最近一次成功收信在 2 分钟前**」。
两句话不可能同时为真 —— 而**第二句是我们自己编的**（见 §5）。

## 2. 量出来的事实

在服务器上用 `cityumail` 身份真连一次（只读，见
`docs/` 之外的临时脚本：LOGIN → EXAMINE → LIST → STATUS）：

```
LOGIN   -> OK [b'LOGIN completed']
EXAMINE INBOX -> NO [b'EXAMINE Unsafe Login. Please contact kefu@188.com for help']
SELECT  INBOX -> NO [b'SELECT Unsafe Login. Please contact kefu@188.com for help']
LIST    -> OK      （能列出所有文件夹）
STATUS  INBOX (MESSAGES 24 UIDVALIDITY 1) -> OK    （能读到 24 封）
```

**密码是对的、登录是成功的、邮箱里有 24 封信** —— 被拒的只有「打开收件箱」这一步。
这就是 163/126（Coremail）的风控：它认为这个客户端**没资格碰邮件正文**。

## 3. 根因：163 要求客户端先报名（RFC 2971 `ID`）

同一把授权码、同一分钟，四条独立连接交替做 A/B/A/B：

| 顺序 | `EXAMINE` 结果 |
|---|---|
| A 不发 `ID` | ✘ `NO EXAMINE Unsafe Login…` |
| B **登录前**发 `ID` | ✔ `OK [READ-ONLY] Examine completed` |
| C **登录后**发 `ID` | ✔ `OK [READ-ONLY] Examine completed` |
| D 不发 `ID`（重复） | ✘ 仍被拒 |
| E 登录前发 `ID`（重复） | ✔ 仍成功 |

交替重复排除了「风控自己过一会儿就软了」这种解释：**差别只在有没有发 `ID`**。
`ID` 是 RFC 2971 的可选命令，客户端用它自报家门（名字/版本/厂商）；
Coremail 拿它当作「这是不是一个正常的邮件客户端」的判据，
而 **Python 的 `imaplib` 永远不会自己发它**。

**所以：163 从第一天起对我们就是坏的**，只是我们一直不知道 —— QQ 和 Gmail 都不看这个，
而腾讯云香港的出口 IP 又正好是这类风控最敏感的地方。

## 4. 改法（`pilot_app/mailio.py`）

```python
identify_client(client)      # 连上就报名：ID ("name" "CityU Mail Pilot" "version" … )
client.login(...)
if not identified:
    identify_client(client)  # 有些服务器只认登录之后的；实测两种顺序在 163 上都有效
status, data = client.select("INBOX", readonly=True)
```

三条性质：

* **只在服务器声明了 `ID` 能力时才发**（QQ 不发就收到不到；多余的命令不做）。
* **永不致命**：发 `ID` 失败绝不影响收信，返回值只是告诉我们「报过名了没」。
* **四条路都接上**：`fetch_new_messages`（worker 收信）、`fetch_recent_messages`（验证）、
  `probe_mailbox`（迁移前勘查）、`idle._connect`（IDLE 监听），外加 `manage` 里那个
  只打印邮件头的排查工具。

### 4.1 埋在下面的第二个坑：`imaplib` 只认固定动词表

第一版就写成了 `client._simple_command("ID", …)`，然后在**真机上照样失败**。
原因：`imaplib` 的 `_command()` 会先查 `imaplib.Commands[name]`，**`ID` 不在表里**，
于是它在**发出任何一个字节之前**就抛 `KeyError`；而那个 `except Exception: return False`
把它吞了 —— 看起来像「服务器不喜欢这个命令」，实际是**我们什么都没发**。

修法是 `imaplib` 自己的 `xatom()` 干的那件事：把动词登记进表（三个状态都允许）。
没有用 `xatom()` 是因为它要求服务器回一条 `* ID` 未标记响应，而**登录前 163 只回 tagged OK**
（实测），用它会拿到 `KeyError`。

### 4.2 教训：假客户端把真 bug 藏住了

修好之前，单测是**全绿**的。因为那批测试用的假客户端**自己实现了 `_simple_command`** ——
它从来不走 `imaplib` 的命令表，所以登记与否它都不在乎。
现在多了一个 `RealImaplibTests`：**真的 `imaplib.IMAP4_SSL`、真的命令表、真的标签记账**，
只把 socket 换成一个小型假 IMAP 服务器（163 的行为：`LOGIN` 通过，没发过 `ID` 就拒 `EXAMINE`）。
其中一条**反向验证**把 `imaplib.Commands["ID"]` 删掉再跑，失败必须回来 —— 那正是线上发生的事。

**规矩**：测试替身替换得越靠近协议层，越容易把「我们根本没发包」这类 bug 藏起来。

## 5. 顺带修掉的一句假话（运维助手）

`agent._account_lines` 把 `mailboxes.last_polled_at` 标成「**最近一次成功收信**」，
而 `update_mailbox_poll` **失败时也写这一列**（AGENTS.md 里那条老陷阱：有时间戳 = 有人试过 ≠ 通了）。
于是运维助手为这个**从没收到过任何一封信**的账号（`last_uid=0`、库里存着报错）
写出了「最近一次成功收信在 2 分钟前」。

现在这一行是：

```
最近一次尝试收信：2 分钟前，失败（就是下面那条报错；在这之前有没有成功过，这里没有记录）
最近一次收信：8 分钟前，成功                ← 只有错误列为空时才这么说
最近一次收信：从没有记录过
```

## 6. 错误信息不再丢掉服务器自己的话

以前存进库的永远是常量「无法以只读方式打开 INBOX。」—— 后台面板、告警邮件、运维助手
全都照抄这一句，所以**谁也不知道 163 说了什么**，只能上服务器抓包。
现在这句会带上服务器的原话，并在认得出来时给一句可执行的话：

```
无法以只读方式打开 INBOX。（邮箱服务器的原话：EXAMINE Unsafe Login. Please contact kefu@188.com for help）
网易邮箱把这次登录判为「不安全登录」，因此拒绝打开收件箱；请到 163/126 网页版登录一次完成安全验证，
或按它给的邮箱联系客服。
```

`imaplib` 的 `select()` 在收到 `NO` 时**不会抛异常**，它把服务器的应答原样返回 ——
我们以前直接把它扔了。这条修正对下一次「没见过的怪错误」同样有效。

## 7. 验收（都在生产上，只读）

* 部署前：`fetch_recent_messages` 失败；SMTP 登录 `235 Authentication successful`（发信本来就是好的）。
* 部署后（v0.63.77）：**`✔ 成功：UID 1760156415，主题「[Ext] 1」`** —— 真的读出了信。
* worker 随后自己跑了一轮：`last_error` 清空、`last_uid` 前进、**入库 8 封**：
  其中 1 封本校来信**已生成报告并发出（`status=sent`）**，
  另外 7 封（facebook／网易安全提醒／jobsdb 等）**按发件人过滤记为 `skipped`，正文未入库** ——
  过滤与隐私承诺都按设计工作。
* 全站 8 个邮箱：除**同站另一个 163 账号**（**账号已暂停 + 授权码错误**，另一类问题、需要本人重填）之外，
  **其余 7 个 `last_error` 全空**；QQ 与 Gmail 不受这次改动影响。
* 单测 1715 → **1733 全过**（其中 163 行为由真 `imaplib` + 假 socket 驱动）。

## 8. 留给以后的

* **163/126 可以用**，前提是我们先发 `ID`。别再写「163 不支持」。
* 新加一个「服务器说的话」类错误时，**把服务器原话带上**，别自己造一句概括。
* 收到 `NO`/`BAD` 的返回值不要丢 —— `imaplib` 把服务器的解释放在那里。
* **给协议层写替身时，留一条走真库的路。**
